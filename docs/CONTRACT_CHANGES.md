# Contract changes log

Additive changes to shared contract files. Format: `- [owner] file: change — reason`.
- [bsp-core] src/bsp/types.ts: added optional `BspFile.facesLump?: number` (LUMP_FACES or LUMP_FACES_HDR) — HDR-only maps have no LDR face lump; their faces' lightOfs then index `lightingHDR`, and the renderer needs to know which.
- [bsp-core] src/bsp/types.ts: added optional `BspFile.warnings?: string[]` — parse/validation problems (bad lump sizes, out-of-range indices, untested versions) for the loader to surface in `LoadedMap.warnings`.
- [materials] src/map/types.ts: added optional `MaterialDef.textureTransform`, `frames`/`frameRate`, `image2`/`fallbackColor2`/`textureTransform2`, `detail` (+ new `MaterialDetail` interface) — needed for in-game fidelity: $basetexturetransform scaling, AnimatedTexture proxies, WorldVertexTransition displacement blends ($basetexture2 by RenderBatch.alphas) and $detail textures. All optional; renderers that ignore them still get a correct base image.
- [movement] src/physics/movement.ts semantics (no contract file edited): `playerMove(..., frametime, ...)` takes the RAW tick interval and applies `ps.laggedMovement` itself (effective ft = frametime * laggedMovement). ARCHITECTURE "tick order" step 3 says the caller pre-multiplies — do only one: pass `tickInterval`. Also new optional export `movementOptions.rampbugFix` (default true) for a server cvar.
- [materials] src/map/types.ts: added optional `DecodedImage.compressed` (+ new `CompressedImage` interface: DXT1/3/5 mip chain) — opt-in `buildMaterials(..., { compressedTextures: true })` keeps the VTF's original DXT blocks so an S3TC-capable renderer can upload full-resolution textures with 4–8x less memory (surf_summer_ksf: 58 MB DXT instead of 315 MB RGBA). Default off; `data` stays a valid RGBA image (reduced size in that mode).
- [materials] src/map/types.ts: added optional `MaterialDef.envmap` (+ `MaterialEnvmap`), `MaterialDef.waterFogRange`, and `MapRenderData.cubemaps` (+ `CubemapDef`) — cubemap reflections ($envmap on glass, shiny ramps, neon grids) and water fog distances are part of the in-game look; `loadCubemaps(bsp, pak)` in bsp/materials.ts fills `cubemaps`. All optional.
- [bsp-render] src/map/types.ts: added optional `RenderProp.color`, `alpha`, `entity`, `area` and `ambientCube` — prop_dynamic entities (128 on surf_lt_omnific) carry rendercolor tints / renderamt, the game needs the entity index to toggle them, 3D-skybox props (surf_lt_omnific's 3dsb_* models) need their BSP area to be drawn in the sky pass, and props have no lightmap: vrad's leaf ambient cube at the prop's lighting origin is how the engine lights them. All optional; a renderer that ignores them still draws correct geometry.
- [bsp-render] src/map/types.ts: added optional `RenderBatch.decal` — info_overlay geometry (422 overlays on surf_lt_omnific: trims, signs, graffiti) is emitted as batches lying on the world surfaces; the flag tells the renderer to draw them with a depth bias after the opaque world. Optional; without it they still render (lifted 0.25 units off the surface).
- [game-world] src/map/types.ts: added `'map'` to the `ZoneSource` union — timer zones derived from the map's own conventionally named timer triggers (start_trigger / endzone / cpN_trigger / bonusNstart ...), used when there is no SurfTimer preset and to fill the courses/zone types a preset lacks. Additive: existing values unchanged.
- [collision] src/physics/collision.ts (no shared contract file edited; additive API): `new CollisionWorld(brushes, opts?)` takes optional `opts.triangles` (`TriangleSoup` or an array of them: positions, indices, optional per-triangle contents/model) collided natively as two-sided triangles in their own BVH, plus `triangleCount`, `queryTriangles()`, `triangle()`, `triangleBrush()`, `lastHitTriangle` and extra `stats()` fields. Semantics: box/ray traces, testBox and setModelSolid cover triangles; pointContents and queryBox do not (triangles have no volume, like Source displacements). `loadBspMap` now builds displacement collision this way (surf_mesa_fixed: collision phase 3.2 s -> 0.36 s, ~400 MB less memory), so `LoadedMap.collision.brushes` no longer contains displacement prism brushes (world + brush-entity brushes only; use `queryTriangles` for terrain). `LoadBspOptions.displacementCollision: 'prisms'` restores the old prisms; `collectCollisionBrushes` keeps prisms by default (callers doing `new CollisionWorld(set.brushes)` are unchanged) and takes `{ displacements: 'triangles' }` + `createCollisionWorld(set)` for the new path.
- [integration] src/game/api.ts: added optional `RendererApi.setFog?(fog: FogDef | null)` and `RendererApi.capabilities?(): RendererCapabilities` (+ new `RendererCapabilities` interface) — map logic switches fog at runtime (`SetFogController`, wired from `EntitySystem.onFogController`), and the game needs to know whether the device takes S3TC to load DXT textures (`loadBspMap(..., { materials: { compressedTextures: true } })`). Optional: fakes and other renderers need not implement them.
- [integration] src/game/game.ts (no contract file): `MapLoaders.loadBsp(name, data, onProgress?, opts?: BspLoadOptions)` — the game passes `{ compressedTextures }` from the renderer's capabilities.
- [integration] src/map/builtin/list.ts: `BUILTIN_MAPS` / `BuiltinMapInfo` moved here (re-exported unchanged from map/builtin/index.ts) so the list is importable without bundling the builders.
- [integration] src/physics/collision.ts semantics (no contract file): box/ray clipping starts the enter fraction at Source's "never updated" sentinel (-9999) instead of -1, so a move into a face from within DIST_EPSILON is always stopped (fixes players creeping into slanted displacement walls; tests/collision.test.ts, tests/dispcoll.test.ts).
- [integration] src/game/debugapi.ts (no contract file): `window.__surf` gained `setVelocity`, `inSolid`, `zones`, `triggers`, `findRamps`, `renderInfo` for the e2e runner (scripts/e2e.mjs).
- [integration] src/bsp/props.ts semantics (no contract file): `RenderProp.origin/angles` of model entities (prop_dynamic, prop_physics...) now include the root-bone pose of frame 0 of their starting sequence (`DefaultAnim`, else sequence 0) for single-bone models, as the engine draws them (surf_lt_omnific's signs and logos have an "idle" that turns the root 90 degrees: they were edge-on / read mirrored). Static props are unchanged (bind pose). New exports `composePose`, `eulerToQuat`, `RootPose`; `StudioModel.sequencePoses/defaultPose`.
- [game-core] src/game/api.ts: added optional `LoadProgress.loadId?: number`, `mapName?: string`, `recovered?: boolean` — every report the game sends (`'loadprogress'` events and `UiApi.setLoading`) carries the id of its load (grows with every load: a new id = a new load, so the loading screen refreshes its header instead of keeping a failed load's name) and the map being loaded. `recovered: true` on a phase `'error'` report means the map change failed but the previously played map is back (the game returns to 'playing' / 'paused' right after it): show the error briefly (toast), not the error screen.
- [game-core] src/game/api.ts: added optional `GameApi.rawInputActive?: boolean | null` (Game implements it) — whether the pointer lock got raw input (`unadjustedMovement`): null before the first capture, false for a plain lock (browser without raw input, or `m_rawinput 0`). The first fallback also prints advice to the console once (disable "Enhance pointer precision" / mouse acceleration, 100% display scaling). For Settings → Mouse ("Raw input: active / not supported by this browser"). Also optional `GameApi.simulatingWhilePaused?: boolean`: true while the pause menu is open over a ranked run that keeps running (the pause menu shouldn't say "Game paused" then).
- [game-core] src/game/api.ts: added optional `TimerHud.lastSplitLabel?: string` — what the split flash compares: "Stage 2 00:12.345" (a completed stage: `lastSplitDelta` is then vs your best time of that stage, SurfTimer's stage time), "Stage 3" (run split vs the PB), "CP 2", "Finish".
- [game-core] src/game/api.ts: added optional `RenderSettings.zoneStyle?: 'floor' | 'box'` (the field the render agent planned, added here first with the same name/type) — `r_drawzones` is now 0 off / 1 floor outline (default) / 2 full box, sent as `{ drawZones, zoneStyle }`.
- [game-core] semantics (no contract file): `Game.pause(opts?: { freeze?: boolean })` — the pause menu (ESC, `cancelselect`, pointer-lock loss) keeps simulating while a ranked run is running (keys released, the run still counts; `Game.simulatingWhilePaused`), and freezes otherwise as before; `freeze` (and `window.__surf.pause()`) is a hard freeze for deterministic `runTicks` stepping. A hidden tab (`visibilitychange`), a frame gap over 1 s, or a failed map change that returns to the map turns a ranked run into practice (`SurfTimer.interruptRun()`, chat "Timer stopped — run paused, it won't count. Type !r to restart."); never with `?autotest=1`.
- [game-core] semantics (no contract file): `map <name>` / `Game.loadMapByName` validates the name (built-ins, then the catalog) before touching anything: unknown → console `map load failed: <name> not found`, no state change. Every map load keeps the current session aside (not simulated, still in the renderer) until the new map is downloaded and parsed (BSPs over 128 MB drop it before parsing, memory); on failure it comes back (state 'playing'/'paused', chat + console error, `retry` = that map). While loading, `session` is null and `mapName` is the map being loaded, as before.
- [game-core] user cfg files (no contract file): localStorage key `surf.cfg.<name>` (name normalized like `src/ui/cfgfiles.ts`: no path / `.cfg` / `.txt`, lower case, `[a-z0-9_.-]`) — `exec <name>` runs it line by line like Source (`//` comments, quotes, `;`, aliases; unknown commands are reported), `cfg_save <name> "<cmds>"`, `cfg_list`, `cfg_delete <name>` (`src/game/cfgstore.ts`); `autoexec` runs at startup after the saved config. `COMPAT_CVAR_DEFS` (src/game/convars.ts, not in `CVAR_DEFS`): hidden no-effect CS:GO client cvars so pasted autoexecs don't print "Unknown command".
- [game-world] src/game/timer.ts semantics (no contract file): reaching stage N+1 prints "<name> finished Stage N in <time> (PB ±delta | first time)" (stage best per tickrate, saved on ranked runs; worded like the map finish line and not starting with "Stage N", which tests/builtin.test.ts reads as a run split) before the run split "Stage N+1 | <time>"; the end zone completes the last stage; stage practice (`!s N`) reports in the same words (was "Stage N | <time>"). `TimerHud.stageTime` is 0 while the player is inside the current stage's zone. Finish lines say "Rank 1/1" (rank among players, one on a local server; `RunFinishEvent.rank/total` still count your own completions). The PB ghost is shown only while the run clock runs (not in the start zone). New `SurfTimer.interruptRun()` (also on `TimerExtras` in commands.ts).
- [bsp-render] src/physics/types.ts semantics (no contract file edited): `Brush.model` / `TraceResult.model` can be `PROP_COLLISION_MODEL` (-2, exported by src/bsp/props.ts and src/bsp/phy.ts) — `loadBspMap` now adds the collision hulls of static props and solid prop_dynamic / prop_physics entities to `LoadedMap.collision` (bsp/phy.ts: .phy convex pieces as brushes with bevels; surf_summer_ksf's start-room floor and ramps are props). Negative, so code that treats `model > 0` as a brush entity ignores props and movement reports ground model 0 on them (static props belong to the world entity in Source); `collision.setModelSolid(PROP_COLLISION_MODEL, false)` switches all prop hulls off (buildMapProps does so while it lights props: the light cache traces the world only). New optional `LoadBspOptions.propCollision` (default true).
- [game-core] removed `GameApi.simulatingWhilePaused` (and the pause menu's "run keeps going" state): every pause now freezes the world, timer included, and the run still counts on resume; a hidden tab pauses the game instead of making the run practice; a frame gap no longer makes the run practice.
- [ksf] src/game/api.ts: added optional `HudState.ksfWr?: KsfWrHud | null` (new `KsfWrHud { time, name, board }`) — the KSF world record of the map's main course (ksf.surf, through the local server) for the HUD side panel and the pause menu; null / absent when unknown (no local server, built-in map, no records). Added optional `GameApi.watchKsfWr?(): void` — the map browser's "Watch WR" (the `!wrreplay` command without its toggle-off). Optional: UIs and fakes that ignore them are unaffected.
- [ksf] src/game/replay.ts (no contract file; additive): `ReplayData` gained optional `startFrame` (prestrafe frames before run time 0) and `velocities` (3 floats per frame); `sampleReplay` honours both (`ReplaySample.velocity`, negative times reach into the prestrafe) and is unchanged for our own recordings. `ReplaySystem` gained `setWrReplay` / `getWrReplay` / `wrGhostAt` (gold "KSF WR" ghost, id `ksf:wr`) and `spectateData` (spectate any replay); `spectateView(t)` counts `t` from the replay's first frame. New `replayFromKsf(parsed, map, opts)`. `sampleReplay` snaps to the nearer frame across a teleport (frames more than `REPLAY_TELEPORT_DISTANCE` = 1000 units apart; new `isTeleportStep`) instead of interpolating, for every replay.
- [ksf] src/game/timer.ts (no contract file; additive): optional `SurfTimer.finishExtras(group, time, ranked)` — segments appended to the finish line (the game adds " | +1.234 vs KSF WR").
- [ksf] src/game/commands.ts (no contract file): `!wr` is now the KSF world record (`!wr <n>` and a missing KSF answer still show the local top like `!top`); `CommandContext` gained optional `ksfWorldRecord()`, `loadKsfWrReplay(opts)` (its result may be `deferred`: loaded while a run started, not watched; or `cancelled`) and `cancelKsfWatch()` (a pending `!wrreplay` download watch). New cvar `surf_ghost_wr` (0).
- [physics] src/physics/collision.ts semantics (no contract file): the brush / triangle clip uses Source's "missed" test (`d1 > 0 && d2 > 0` skips the brush) instead of Quake 3's (`d2 >= DIST_EPSILON || d2 >= d1`), clamps entering fractions at 0 like Source, and resolves a hit at 0 (the box starts inside the epsilon shells of every face it enters, where Source goes by side / BSP order) by the real crossings: the face crossed last is reported, and of brushes hit at 0 the one entered first. Every entering plane counts, however small the move into it (crossings pulled back by more than the -9999 sentinel are no longer skipped: a box creeping up on a steep displacement slope under friction ended in solid). A move that ends within DIST_EPSILON of a face without reaching it is no longer pulled back to the shell (players stopped dead at sub-epsilon ramp seams, e.g. surf_utopia_njv's ramp into the box; tests/ramp_seams.test.ts, tests/collision.test.ts). `CLIP_NOISE` is gone. tests/helpers/movement_world.ts RefWorld follows the same rules.
- [physics] src/physics/collision.ts: static-prop hulls (`PROP_HULL_MODEL` = -2) keep the pre-4d1106b touch rule (Quake 3's "missed" test, CLIP_NOISE, old face choice) and lose ties at fraction 0 to brushes / triangles (Source traces props through VPhysics); `tests/prop_hulls.test.ts`.
- [ksf] src/maps/ksfreplay.ts: KSF replay format v3 (since about August 2026): 24 + 4W header bytes (W client-setting words), 524-byte event blocks, 72-byte frames (the v2 40 bytes + flags, ticks, forward/side move...); v2 still read, unknown versions rejected; `tests/ksf_replay_v3.test.ts`.
- [renderer/perf] src/game/api.ts: added optional `RenderSettings.antialias?: number` — MSAA samples of the 3D view (`mat_antialias`: 0 off, 2, 4, 8; the renderer clamps to what the device supports and rebuilds its framebuffer live). Optional: UIs and fakes that ignore it are unaffected.
- [renderer/perf] src/map/types.ts: added optional `MapRenderData.vis?: MapVisibility | null` and the `MapVisibility` interface (decompressed PVS rows, world tree, leaf clusters) — built by `bsp/visibility.ts` in `loadBspMap`, used by the renderer's PVS culling (`render/pvs.ts`). src/game/api.ts: optional `RenderSettings.novis?: boolean` (`r_novis`), optional `GameApi.graphicsInfo?(): GraphicsInfo | null` and the `GraphicsInfo` interface (GPU name, MSAA samples, framebuffer size) for Settings → Video. Optional: fakes and loaders that ignore them are unaffected.
- [renderer/perf] src/game/api.ts: added optional `RenderSettings.skyStencil?: boolean` (`r_skystencil`, default true) — an expensive sky (3D skybox, procedural sky) is drawn after the opaque world on the stencil's sky samples; false draws it first, everywhere, without a stencil (debug / GPU cost comparison). Optional: renderers that ignore it are unaffected.
